# Regression reference: Pixhawk 6C (fmu-v6c), PX4 armed take-off with the
# in-process Hakoniwa aircraft
# Checked by athrill-target-stm32 examples/px4-v6c-hakoniwa/verify-armed-inproc.sh.
#
# Valid only for this firmware: px4_fmu-v6c_default.elf of the
# athrill-target-stm32 release px4-v1.17.0-fmu-v6c (PX4 v1.17.0, make
# px4_fmu-v6c_default in px4io/px4-dev:v1.17.0-beta1; SHA-256 in the release's
# SHA256SUMS). A rebuild may not be bit-identical; with another firmware the
# values are not compared.
# Aircraft: Hakoniwa Drone 5.0.0, x500-px4-sitl, lockstep, timeStep 0.001,
# randomSeed 12345.
#
# Recorded 2026-11-07 with athrill-target-stm32 014c1b0 and athrill-device
# 934895f; the C path and the Devicetree path give the same values.
# Re-recorded 2026-11-08 (athrill-target-stm32#62 work): the reference was
# only reproducible with seed images (fram.bin, sd.img) left from an earlier
# first boot, because prepare.sh makes them only when they are absent. A
# first boot with the current models gives different seeds: the gyro
# offsets PX4 commits during it differ ([0.000 0.000 0.000] before,
# [-0.000 -0.000 0.000] now), so F-RAM parameters and the whole armed run
# differ. The first boot is deterministic (same seeds twice; the same
# with athrill-target-stm32 at devicetree-only and with the old core), and
# the armed run with these seeds gave the same values with five builds,
# each "armed and took off". The verification now makes the seeds anew
# every time and checks them first (seed_sha256).
# Instructions re-recorded 2026-11-11: a timer now reports the update that
# loads a pending preload register (CCRx, ARR, PSC) as an event, so that tick
# skip ticks its PWM readers there. The extra batch boundaries change the
# printed count (it adds the clocks of a branch to itself on a path that
# depends on the batch), 5248904847 -> 5248909950; the console, the PWM trace
# and the time-stamped sensor-device trace are unchanged, with the interpreter,
# with tick skip and with the JIT and tick skip.
# Re-recorded 2026-11-14 with athrill-device 6b6f588 for a published firmware:
# the earlier reference firmware (8719b2ea...) was never published and could
# not be rebuilt bit-identically, so the reference moved to the ELF of the
# athrill-target-stm32 release px4-v1.17.0-fmu-v6c (e192cd79...). The models
# also changed the run since the last recording: the DMA sets HTIF for a
# one-item transfer (#102; NuttX's H7 serial driver freed its TX buffer only
# then) and the SD card's D0 reads high (#103; each SD write had waited 260 ms).
# Two runs gave identical values ("armed and took off"); the tick order is
# unchanged. Aircraft: Hakoniwa Drone PRO (v5 code with the motor status
# interface), x500-px4-sitl with randomSeed 12345, in process.
# Re-recorded 2026-11-14 (athrill-target-stm32#94): the x500 parameter script
# set SENS_GPS0_DELAY and SYS_AUTOCFG_CAL, which PX4 v1.17.0 does not have, so
# they never took effect. It now sets EKF2_GPS_DELAY 100 (the v1.17.0 name of
# the same delay; default 110) and no longer SYS_AUTOCFG_CAL, so the seeds and
# the run changed. Two runs, each with its own first boot, gave identical
# values ("armed and took off"); the tick order is unchanged.
